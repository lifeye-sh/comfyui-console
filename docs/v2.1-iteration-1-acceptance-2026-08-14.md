# V2.1 第 1 轮验收记录

> 日期：2026-08-14
> 范围：AI 短剧领域模型与数据库迁移

## 已完成

- 建立 `ShortDramaProject → Episode → Scene → Shot → Take` 核心生产层级。
- 建立 `ProjectBrief` 创作简报和乐观锁版本字段。
- 建立角色、角色造型、场景设定和道具模型。
- 建立剧本版本树、当前版本唯一约束和来源快照。
- 建立独立 `CreativeJob` 模型，和现有 ComfyUI Task 保持执行边界。
- 建立项目资源、镜头任务和 Take 的关联模型。
- 所有新增领域表均直接保存 `owner_id`。
- 项目采用软删除；Resource 和 Task 不随项目级联删除。
- 每个镜头在数据库层最多只能采用一个 Take。
- CreativeJob 和 ShotTaskLink 建立用户级幂等键。
- 新增 Alembic `0008_short_drama_foundation` 迁移。
- 迁移同时兼容全新数据库和已经运行旧版本的数据库。
- 修正 Task ORM 遗漏的 `ix_tasks_status_node_id` 索引声明，消除既有迁移漂移。

## 验证结果

- ORM 全部表可在空 SQLite 数据库创建。
- 项目、分集、场景、剧本版本和镜头层级可正常持久化。
- 第二个已采用 Take 会被数据库唯一约束拒绝。
- 全新数据库执行 `alembic upgrade head` 到达 `0008 (head)`。
- 模拟旧数据库执行 `0008` 可创建全部短剧表。
- `alembic check` 返回 `No new upgrade operations detected.`。
