# comfyui-console 开发计划（Claude Code 协作版）

> 版本：v1.0　日期：2026-08-05
> 适用范围：本文档是**计划文档**，不包含任何业务代码。开发执行由 Claude Code 按任务卡逐会话完成，人负责评审与验收。
> 依据文档：[架构 v0.2](architecture.md)、[功能清单 v0.2](feature-list.md)、[功能详细规格 v0.3](feature-specification.md)

## 1. 协作模式

- **任务卡驱动**：全部开发拆分为编号任务卡（CC-XX）。每个 Claude Code 会话只执行一张任务卡，会话开场把任务卡内容 + 相关文档章节交给 Claude Code。
- **文档先行**：任务卡的"输入文档"列明依据章节；实现与文档冲突时先回改文档，再实现。
- **验收闭环**：每张任务卡附可执行的验收方式（命令或操作场景）。验收通过 → 约定式 git 提交 → 勾选任务看板 → 进入下一张卡。
- **阶段门禁（Gate）**：每个 Phase 末尾设联调验收卡，人按验收单逐条确认后才进入下一阶段。
- **规模标尺**：S = 半个会话以内；M = 约一个会话；L = 一至两个会话（必要时拆卡）。

## 2. 前置条件（开工前一次性确认）

- [ ] 本机安装 Python 3.11+、Node.js 20+、Git
- [ ] 本地 ComfyUI 运行正常（`http://127.0.0.1:8188`），并能导出一个可用文生图工作流的 API JSON（作为联调基准）
- [ ] 磁盘剩余空间充足（建议 ≥ 20GB，资源存储与虚拟环境占用）
- [ ] 在 Claude Code 中以 `E:\AIAgents\claude\comfyui-console` 为项目根目录打开
- [ ] `git init` 完成，首次提交包含全部 docs/

## 3. CLAUDE.md 规划（CC-00 产物，后续持续维护）

项目根目录的 `CLAUDE.md` 是 Claude Code 的常驻上下文，内容约定：项目一句话简介；文档地图（四个 docs 文件及各自版本）；技术栈与目录结构；常用命令（起后端/起前端/迁移/测试）；编码规范（Python 类型注解、异步约定、前端 Composition API + TS）；当前阶段与任务看板链接；禁忌（不改 docs 编号语义、不绕过验收命令）。**每完成一个 Phase 更新一次 CLAUDE.md 的"当前阶段"部分。**

**CC-01 数据库基线与核心模型**
- 输入：架构 §8（users, nodes, generation_types, workflows, workflow_versions, batches, tasks, task_events, task_resources, resources, settings）

**CC-02 认证与用户**
- 输入：架构 §9 认证/用户分组；规格 §10
- 产出：JWT 登录/刷新/me、管理员种子用户（环境变量配置初始口令）、权限依赖注入、用户管理 API
- 验收：curl 完成 login→me→refresh 全流程；错误口令/过期令牌返回统一中文错误码

**CC-03 节点管理 + ComfyUIClient**
- 输入：架构 §4.2；规格 §9
- 产出：节点 CRUD + probe 接口；ComfyUIClient（HTTP + WS 长连接、断线重连、事件归一化 TaskEvent）；节点状态字段随心跳更新

**CC-04 资源服务**
- 输入：架构 §6、§8 resources；规格 §6
- 产出：StorageProvider 抽象 + local_fs 实现；上传（MIME/大小/内容探测校验）、sha256 去重、图片缩略图（Pillow）、下载/读取接口
- 验收：重复上传同一文件只存一份；上传 exe 伪装 jpg 被拒；缩略图生成且列表接口返回 thumb 地址

**CC-05 批次与任务 API**
- 输入：架构 §3/§4.4/§9 批次分组；规格 §0.4
- 产出：batches CRUD、行（DRAFT Task）增删改、提交校验（必填/资源/类型工作流存在）、submit/cancel/retry 接口
- 验收：接口级测试覆盖：建行→改行→提交→状态 DRAFT→PENDING；无默认工作流的行校验失败且不阻塞其他行

**CC-06 调度器与执行闭环**
- 输入：架构 §4.4；规格 §5
- 产出：QueueProvider + db_queue；Dispatcher asyncio 循环；prompt_builder（M1 支持 text/int/seed/image 类型）；输入推送 `/upload/image`；`POST /prompt` 提交与 prompt_id 绑定
- 验收：对本地节点提交一个文生图任务，节点队列可见该 prompt；并发不超过节点 max_concurrent；提交失败自动重排

**CC-07 输出回收与素材库 API**
- 输入：架构 §4.4 完成回收、§6
- 产出：executed→/history→/view 回拉→入库→SUCCESS；资源列表/筛选/分页接口
- 验收：任务完成后输出图片出现在资源库接口；任务参数快照与节点响应可查询

**CC-08 WS 网关**
- 输入：架构 §5.3、§9 实时分组
- 产出：`/ws/events` 鉴权连接、按 task/batch 订阅、事件广播、断线重连对账接口约定
- 验收：执行任务时 WS 客户端收到 progress/completed 事件序列；无 token 连接被拒

**CC-09 前端骨架**
- 输入：架构 §5.1-5.3；功能清单附二菜单
- 产出：登录页、响应式布局（桌面侧边栏/移动端底部 Tab）、路由守卫、axios 封装（JWT 刷新）、WS 客户端（自动重连）、Pinia stores 骨架
- 验收：登录后进入首页；刷新保持会话；WS 连接建立；移动端宽度下 Tab 正常

**CC-10 文生图生成页（M1 版）**

- 产出：类型头部、全局提示词 1/2、默认宽高/种子、BatchGrid 任务行表格（提示词/宽高/种子/操作）、添加/复制/删除行、批量生成、保存批次

## 9. 验证与质量策略

- **后端**：每张后端卡附带 pytest（接口级优先，ComfyUI 交互用 mock 客户端）；Gate 前必须全绿。
- **前端**：每卡验收含 `vite build` 无错、TS 类型检查通过；关键页人工走查。
- **联调**：以本地 ComfyUI 为基准环境；Phase 3 起增加第二实例。
- **提交纪律**：一卡一提交（`feat(scope): CC-XX ...`）；文档变更单独 `docs:` 提交。
- **上下文管理**：CLAUDE.md 保持精简；每会话只带当前任务卡与相关章节，避免超长上下文漂移。

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| ComfyUI API 版本差异导致联调失败 | CC-03 先锁定本地 ComfyUI 版本并记录；client 做响应容错 |
| 任务卡粒度过大，单会话做不完 | 按验收点拆卡，剩余部分立新卡并在看板标注拆分来源 |
| 文档与实现漂移 | Gate 验收单含"文档一致性"条目；漂移先改文档 |
| 音视频大文件处理性能 | CC-25/CC-31 专门处理；超阈值文件走异步处理 |
| 并行开发冲突 | 严格串行执行看板；同一文件不跨卡并行修改 |
