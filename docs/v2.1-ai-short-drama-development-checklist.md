# ComfyUI Console V2.1 AI 短剧开发清单

> 制定日期：2026-08-14
> 上位产品规划：[AI 短剧产品设计规划](./ai-short-drama-product-plan.md)
> 迁移参考：[Novel2Script 合并开发计划](./v2.1-novel2script-integration-plan.md)
> 版本目标：完成“前期创作 + 镜头进入现有生成系统”的第一个可用闭环

## 1. V2.1 发布目标

用户能够在一个短剧项目中完成：

```text
创建项目
→ 输入创意或导入小说/剧本
→ 形成分集、场景和剧本版本
→ 维护角色、场景与道具设定
→ 将场景拆成可编辑镜头
→ 从镜头创建现有 ComfyUI 任务
→ 自动将任务结果回写为镜头 Take
→ 在项目中预览和采用结果
```

V2.1 的完成标准不是“页面已经出现”，而是上述链路可以由普通用户从头到尾完成，刷新、失败重试和重新登录不会破坏数据。

## 2. 优先级与范围

### 2.1 优先级定义

- `P0`：V2.1 发布必须完成，缺少即不能发布。
- `P1`：应随 V2.1 交付；若延期必须有不破坏主流程的降级方案。
- `P2`：体验增强，可转入 V2.1.x。

### 2.2 V2.1 明确不做

- 完整视频剪辑时间线、转场和最终编码合成；
- 完整配音、音效、BGM 和字幕工作台；
- 自动识别视频中的角色一致性和复杂连续性质检；
- 根据能力标签自动选择最优工作流；
- 多人实时协同、在线批注审批流；
- 一键生成整部短剧；
- 工作流链式编排和自动补救；
- 专业剪辑软件工程文件导出。

以上能力分别进入 V2.2、V2.3 或 V2.4，不能在 V2.1 开发中临时扩张范围。

## 3. 核心产品决策

- [ ] `P0` 确认 `ShortDramaProject` 为新的项目根对象，不复用 Task 表表示项目。
- [ ] `P0` 确认 `Episode → Scene → Shot → Take` 为固定生产层级。
- [ ] `P0` Novel2Script 逻辑迁入当前后端，不保留第二套服务、登录和数据库。
- [ ] `P0` LLM/文档解析使用 `CreativeJob`，ComfyUI 生成继续使用现有 `Task`。
- [ ] `P0` 使用关联表连接 Shot、Task、Take，不用素材文件夹名称表达业务关系。
- [ ] `P0` 所有领域数据必须有 `owner_id`，项目查询默认只返回当前用户数据。
- [ ] `P0` V2.1 使用功能开关，关闭时现有 V2 菜单、API 和业务行为不变。
- [ ] `P1` 确认项目删除采用软删除；生成资源仍按现有回收站策略处理。
- [ ] `P1` 确认普通模式只显示创作字段，高级模式才显示工作流和任务参数。

## 5. 第 1 轮：领域模型与数据库迁移

目标：建立项目、剧本结构、设定、镜头和任务关联的可靠数据底座。

### 5.1 核心表

- [ ] `P0` `short_drama_projects`：名称、简介、来源类型、规格、阶段、状态、封面、owner、软删除。
- [ ] `P0` `project_briefs`：题材、受众、基调、平台、比例、集数、单集时长、质量档位和全局约束。
- [ ] `P0` `episodes`：集号、标题、梗概、目标时长、顺序和状态。
- [ ] `P0` `scenes`：场号、内外景、地点、时间、正文、剧情目的、顺序和状态。
- [ ] `P0` `shots`：镜号、叙事目的、画面描述、动作、表情、景别、机位、运镜、时长、顺序和生产状态。
- [ ] `P0` `takes`：镜头候选版本、资源、来源任务、采用状态、参数快照和生成溯源。
- [ ] `P0` `shot_task_links`：Shot、Task、Take、用途和状态关联。

### 5.2 设定与剧本表

- [ ] `P0` `characters`：角色基本设定、外观约束和来源定位。
- [ ] `P1` `character_variants`：服装、发型、年龄阶段和参考资源。
- [ ] `P0` `locations`：地点、空间、时间、光线、色彩和固定物件。
- [ ] `P1` `props`：道具外观、归属和连续性说明。
- [ ] `P0` `story_versions`：剧本版本、父版本、来源、摘要和当前版本标识。
- [ ] `P0` `creative_jobs`：类型、状态、进度、日志、错误、输入输出和重试信息。
- [ ] `P1` `project_resource_links`：项目对象与现有 Resource 的多用途关联。

### 5.3 数据规则

- [ ] `P0` 为 owner、project、episode、scene、shot、status 和 order 字段建立必要索引。
- [ ] `P0` 顺序字段支持事务内重排，不依赖数组下标临时计算。
- [ ] `P0` 删除上层对象前检查下层对象，避免级联删除任务和文件。
- [ ] `P0` Take 保存不可变的工作流版本、参数和素材引用快照。
- [ ] `P0` 采用的 Take 在每个 Shot 内最多一个，数据库和服务层都校验。
- [ ] `P0` Alembic 升级支持已有数据，应用回滚时不执行破坏性降级。
- [ ] `P1` 新增审计事件类型：创建项目、改剧本、拆镜、创建任务、采用 Take、删除/恢复。

### 5.4 本轮测试与验收

- [ ] 全新数据库可以升级到 head。
- [ ] 现有数据库升级后原任务、素材和工作流数据不变。
- [ ] 用户之间无法读取、修改或关联对方项目数据。
- [ ] 层级新增、编辑、重排、软删除、恢复和并发更新测试通过。

## 6. 第 2 轮：短剧项目与创作简报

目标：用户可以创建、查找和持续编辑一个短剧项目。

### 6.1 API

- [ ] `P0` 项目列表、详情、新建、编辑、软删除和恢复 API。
- [ ] `P0` 支持名称、状态、创建时间和最近更新时间查询。
- [ ] `P0` 创作简报读取、保存和字段校验 API。
- [ ] `P0` 项目概览聚合 API，避免首页发起大量逐项请求。
- [ ] `P1` 项目封面关联/解除现有素材 API。
- [ ] `P1` 保存用户最近访问项目和项目内最近位置。

### 6.2 前端

- [ ] `P0` “短剧项目/全部项目”页面：卡片与列表、搜索、状态筛选、分页和空状态。
- [ ] `P0` “新建短剧”向导：起点、创作信息、成片规格、视觉方向和确认。
- [ ] `P0` 项目内导航：概览、剧本、角色与世界、分镜、镜头生产。
- [ ] `P0` 项目概览：阶段进度、分集统计、待处理项、最近 Take 和失败任务。
- [ ] `P0` 创作简报编辑：自动保存、未保存提示和离开保护。
- [ ] `P0` 页面不得因任务轮询刷新整个视图或清空正在填写的数据。
- [ ] `P1` 移动端项目卡片、概览和创作简报可用。

### 6.3 本轮验收

- [ ] 两个浏览器标签同时修改时给出版本冲突提示，不静默覆盖。
- [ ] 项目列表首屏和概览无 N+1 请求及明显卡顿。

## 7. 第 3 轮：文档导入与 CreativeJob

目标：把 Novel2Script 的输入、解析和长耗时作业安全接入现有平台。

### 7.1 导入

- [ ] `P0` 支持 TXT、DOCX、EPUB 上传和从素材库选择。
- [ ] `P0` 校验扩展名、MIME、文件大小、编码和空内容。
- [ ] `P0` 原始文件进入现有素材库并关联项目，不使用独立 uploads 目录。
- [ ] `P0` 提取章节、段落和稳定来源定位。
- [ ] `P0` 展示解析结果、异常章节、忽略项和重新解析入口。
- [ ] `P1` 支持直接粘贴故事梗概或剧本文本。
- [ ] `P1` 支持无原作的“一句话创意”建立初始大纲作业。

### 7.2 CreativeJob

- [ ] `P0` 建立独立 Story Worker，不占用 HTTP 请求线程和 ComfyUI Task Worker。
- [ ] `P0` 支持 queued/running/succeeded/failed/cancelled 状态。
- [ ] `P0` 支持阶段进度、心跳、结构化日志、取消和失败重试。
- [ ] `P0` Worker 重启后回收超时 running 作业，保证幂等执行。
- [ ] `P0` 登录和普通 API 不得被排队的 CreativeJob 阻塞。
- [ ] `P1` 作业列表可与任务中心聚合展示，但执行器保持分离。
- [ ] `P1` AI 服务配置支持 OpenAI 兼容端点、模型、超时和密钥安全存储。

### 7.3 本轮验收

- [ ] 三种文件均能导入并生成稳定章节结构。
- [ ] 解析进行时用户可继续使用系统和登录。
- [ ] Worker 被终止后，作业能够恢复、重试或明确失败，不永久卡在运行中。
- [ ] 同一幂等键重复提交不会创建两份项目结构。

## 8. 第 4 轮：剧本、分集与版本管理

目标：用户可从原作或创意形成短剧结构，并始终保留人工控制权。

### 8.1 编排能力

- [ ] `P0` 迁移人物/地点/关系/事件抽取逻辑。
- [ ] `P0` 迁移场景切分、元素抽取和对白归属逻辑。
- [ ] `P0` 生成分集建议、场景顺序和短剧节拍建议。
- [ ] `P0` 改编选择以候选方案展示，用户确认后才写入新版本。
- [ ] `P0` 所有 AI 输出执行 JSON Schema 和引用完整性校验。
- [ ] `P0` AI 输出失败时保留原始响应摘要和可理解的失败原因。
- [ ] `P1` 提供三幕结构、冲突密度、结尾钩子和 Fidelity 基础报告。

### 8.2 剧本工作台

- [ ] `P0` 左侧分集/场景树，中部剧本文本，右侧属性/建议的桌面布局。
- [ ] `P0` 支持新建、编辑、删除、复制和拖动分集/场景。
- [ ] `P0` 支持动作、对白、旁白、转场等基本元素语义。
- [ ] `P0` 每次 AI 编排或优化生成新版本，不覆盖当前版本。
- [ ] `P0` 版本列表支持命名、切换、比较和“恢复为新版本”。
- [ ] `P0` 自动保存只保存人工草稿，不触发 AI 作业。
- [ ] `P1` 原文与剧本对照定位。
- [ ] `P1` Fountain、TXT、YAML 导出并写入素材库。
- [ ] `P2` 局部场景 AI 精修。

### 8.3 本轮验收

- [ ] 从导入小说到形成首版分集剧本的主流程可完成。
- [ ] 用户拒绝 AI 建议后，当前版本不发生变化。
- [ ] 任意旧版本都可以查看并恢复为新版本。
- [ ] 场景引用的角色和地点不存在时会阻止确认并指出位置。

## 9. 第 5 轮：角色与世界设定

目标：建立镜头生产使用的统一角色、场景和道具来源。

### 9.1 设定管理

- [ ] `P0` 从故事圣经同步角色、地点和关系，并保留来源定位。
- [ ] `P0` 角色卡：姓名、别名、身份、年龄感、外形、性格、关系和禁用特征。
- [ ] `P0` 场景卡：地点、空间、时间、天气、光线、色彩和固定物件。
- [ ] `P1` 道具卡：外观、归属、出现范围和连续性说明。
- [ ] `P1` 角色造型版本：服装、发型、妆容和参考资源。
- [ ] `P0` 图片、视频、音频引用均从素材库选择并提供预览。
- [ ] `P0` 引用素材删除时显示被哪些设定和镜头使用。
- [ ] `P1` 角色和场景可标记“已确认/未确认”。

### 9.2 设定生成衔接

- [ ] `P0` 角色卡可创建图片生成任务草稿。
- [ ] `P0` 场景卡可创建图片生成任务草稿。
- [ ] `P0` 生成结果可回写为角色/场景候选参考图。
- [ ] `P1` 支持从候选中设置主参考图。
- [ ] `P2` 多角度、表情和服装测试组合生成。

### 9.3 本轮验收

- [ ] 从剧本抽取的角色和场景可人工校正，不会在重新抽取时被静默覆盖。
- [ ] 角色或场景任务完成后，结果在项目内可见且能设为参考。
- [ ] 设定引用和素材预览在桌面端、移动端均可用。

## 10. 第 6 轮：分镜与镜头卡

目标：把确认剧本转换成可生产、可排序、可追踪的镜头清单。

### 10.1 场景拆镜

- [ ] `P0` 从指定剧本版本和 Scene 生成 Shot 建议。
- [ ] `P0` 每个 Shot 保存来源剧本版本和 Scene，保证溯源。
- [ ] `P0` AI 拆镜只创建草稿；用户确认后进入“可生成”。
- [ ] `P0` 重新拆镜时保留已确认镜头，提供替换/追加/比较选择。
- [ ] `P0` 校验镜头时长总和与场景/单集目标时长。

### 10.2 镜头编辑

- [ ] `P0` 镜头字段：叙事目的、画面、角色、场景、动作、表情、对白、景别、机位、运镜、时长。
- [ ] `P0` 素材字段：首帧、尾帧、人物参考、姿态图、参考视频和音频。
- [ ] `P0` 支持新增、复制、拆分、合并、删除和拖动镜头。
- [ ] `P0` 支持卡片和表格两种视图。
- [ ] `P0` 支持按集、场景、状态和角色筛选。
- [ ] `P0` 镜头编号由服务端在事务内维护，避免并发重复。
- [ ] `P1` 批量修改时长、比例、质量档位和状态。
- [ ] `P1` 故事板视图显示 2:3 缩略图和镜头节奏。
- [ ] `P1` 显示未确认角色/场景、缺失素材和工作流不可用等阻塞项。

### 10.3 本轮验收

- [ ] 一个场景可以生成、编辑和确认多个镜头。
- [ ] 拖动、删除和插入后镜头编号连续且无数据错位。
- [ ] 刷新页面不会丢失正在编辑的已保存镜头。
- [ ] 50 个镜头的单集列表仍可顺畅编辑和筛选。

## 11. 第 7 轮：Shot、Task 与 Take 生产闭环

目标：复用现有生成系统，完成 V2.1 最重要的纵向闭环。

### 11.1 Shot → Task

- [ ] `P0` 用户为镜头选择一个当前类型可用的生成类型/工作流。
- [ ] `P0` 将镜头画面描述、角色/场景信息组装为可编辑提示词草稿。
- [ ] `P0` 将项目比例、质量档位、镜头时长和引用素材填入对应任务参数。
- [ ] `P0` 创建任务前展示最终参数并执行工作流映射校验。
- [ ] `P0` 支持单镜头创建任务和多镜头批量创建任务。
- [ ] `P0` 创建后写入 `shot_task_links`，镜头页显示任务实时状态。
- [ ] `P0` 重复点击使用幂等键防止创建重复任务。
- [ ] `P1` 支持保存“本项目默认生成类型/工作流”。

### 11.2 Task Result → Take

- [ ] `P0` 任务每个输出文件分别建立 Take 产物关联，支持单任务多文件。
- [ ] `P0` 回写保存任务、工作流、参数、输入素材和输出资源快照。
- [ ] `P0` 结果直接关联项目和镜头，不依赖任务结果文件夹定位。
- [ ] `P0` 任务成功但回写失败时进入可重试的补偿队列，不能把生成任务误判为失败。
- [ ] `P0` 后台补偿操作幂等，不重复创建 Take。
- [ ] `P0` 失败任务在镜头中显示明确原因和重新生成入口。
- [ ] `P0` 删除任务时保留镜头；已有关联 Take 时提示影响范围。

### 11.3 Take 审核

- [ ] `P0` 在镜头详情中预览图片、视频和音频 Take。
- [ ] `P0` 显示尺寸、视频/音频时长和生成溯源。
- [ ] `P0` 支持设为采用、取消采用、下载和删除未采用 Take。
- [ ] `P0` 图片预览支持放大、缩小和拖动，视频支持放大播放。
- [ ] `P1` 多 Take 并排比较。
- [ ] `P1` 添加简单返工说明并以现有参数重新生成。

### 11.4 本轮验收

- [ ] 用户从镜头卡最多 3 次主要操作即可提交任务。
- [ ] 图片、视频、音频任务完成后均能自动出现在正确镜头下。

## 18. V2.1 完成定义

V2.1 只有在用户不进入底层任务管理和素材文件夹，也能从项目内完成以下动作时才算完成：

1. 找到自己的项目并继续上次工作；
2. 看懂当前剧本、角色、场景和镜头结构；
3. 知道下一步缺少什么；
4. 从镜头发起正确的图片或视频生成任务；
5. 在原镜头中看到生成结果、参数来源和失败原因；
6. 选择采用版本，或带着原设定重新生成；
7. 在刷新、排队、失败和重新登录后保持数据完整。

达到以上条件，V2.1 才完成了从 ComfyUI 控制台向 AI 短剧生产工作台的第一次实质升级。
