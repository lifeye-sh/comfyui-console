# V2.1 第 4 轮验收记录

> 日期：2026-08-14  
> 范围：改编候选、剧本工作台、分集场景和版本管理

## 后端交付

- 新增 `AdaptationCandidate`，候选方案确认前不会改变当前剧本。
- 基于已解析章节生成忠实原作、均衡改编、高节奏、悬念优先、情感优先五种候选。
- 候选包含分集、场景、结构化剧本元素和原文段落引用；确认前再次执行结构及引用完整性校验。
- 新增分集、场景的创建、修改、删除和重排 API。
- 场景支持动作、对白、旁白、转场四种结构化元素。
- 场景引用校验覆盖当前项目、源文档、章节和段落范围。
- 人工编辑使用 `lock_version` 乐观锁，过期写入返回 HTTP 409。
- 候选确认、人工保存、旧版本恢复都创建新的 `StoryVersion`；历史版本内容不可原地覆盖。
- 旧版本恢复采用“恢复为新版本”，保留完整版本链和父版本关系。
- 新增 `0010` 迁移，并为既有 SQLite 开发数据库补充兼容字段升级。
- 兼容当前 FastAPI/Starlette 对 204 响应和 422 状态常量的严格检查。

## 前端交付

- 新增 `/v2/drama/projects/:id/screenplay` 剧本工作台。
- 编排页支持选择源文档、章节范围、目标集数并预览五种候选。
- 用户明确确认后才写入剧本；重新编排会提示将替换当前人工草稿。
- 桌面端采用“分集场景树 / 剧本编辑 / 原文与版本”三栏布局。
- 移动端采用“结构 / 编辑 / 原文与版本”三页签，无横向工作区溢出。
- 支持分集和场景新建、改名、复制、删除、按钮排序及拖动排序。
- 场景标题、地点、时间、内外景、时长、正文和结构化元素可编辑。
- 场景草稿防抖自动保存，冲突时保留当前输入并提示刷新。
- 右栏显示场景对应原文和不可变版本记录，支持版本结构比较，并可将历史版本恢复为新版本。

## 关键接口

```text
GET  /api/v2/short-drama/projects/{id}/documents/{document_id}/content
POST /api/v2/short-drama/projects/{id}/adaptation-candidates
POST /api/v2/short-drama/projects/{id}/adaptation-candidates/{candidate_id}/confirm
GET  /api/v2/short-drama/projects/{id}/screenplay
POST/PATCH/DELETE /api/v2/short-drama/projects/{id}/episodes...
POST/PATCH/DELETE /api/v2/short-drama/projects/{id}/scenes...
PUT  /api/v2/short-drama/projects/{id}/screenplay/reorder
GET/POST /api/v2/short-drama/projects/{id}/versions
POST /api/v2/short-drama/projects/{id}/versions/{version_id}/restore
```

## 自动化验收

- 候选生成后当前剧本保持为空，确认后才创建分集和首个版本。
- 同一候选重复确认同一方案保持幂等，改选其他方案会被拒绝。
- 人工编辑不会改变历史版本；保存人工版本后生成新快照。
- 任意旧版本可恢复为新的当前版本。
- 场景过期修改返回 409，跨用户读取版本返回 404。
- 全新 SQLite 数据库执行 `alembic upgrade head` 成功，`alembic check` 无模型差异。
- 后端全量测试：76 项通过。
- 前端 TypeScript 检查和 Vite 生产构建通过。

## 已知边界与下一轮

本轮五种候选使用确定性编排器形成可编辑底稿，已经冻结了后续 AI 输出必须遵循的数据契约。第 5 轮接入人物、地点、关系和事件抽取，AI 结果继续采用“候选—校验—人工确认”模式，不直接覆盖正式数据。
