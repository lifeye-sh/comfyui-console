# ComfyUI Console V2.1：Novel2Script 合并开发计划

> 规划日期：2026-08-13
> 规划基线：ComfyUI Console V2，提交 `85bfed0`
> 来源项目：`E:\AIAgents\claude\novel2script`
> 本文档替代“将 Novel2Script 作为独立应用嵌入”的旧思路；原 V2 开发计划继续作为 V2 历史基线保留。

## 1. 版本目标

V2.1 将 Novel2Script 的小说解析、故事圣经、剧本编排、改编决策、质量评分、AI 优化、版本树和行业格式导出能力，合并为 ComfyUI Console 的“剧本创作”模块。

V2.1 不是在现有页面中嵌入第二个站点，也不是同时运行两套后端。合并后用户只使用一套登录、一套权限、一套数据库、一套素材库、一套审计体系和一个 V2 应用壳。

最终形成以下业务闭环：

```text
小说文件
  → 解析章节与段落
  → 故事圣经
  → AI 剧本编排
  → 原文/剧本对照编辑
  → 改编决策与 AI 优化
  → 版本管理与导出
  → 角色/场景/分镜生成草稿
  → 现有 ComfyUI 任务调度
  → 图片、视频、音频进入素材库
```

## 2. 合并原则

### 2.1 必须复用的平台能力

- 使用 ComfyUI Console 用户、角色、JWT 和数据权限，不保留 Novel2Script 的匿名数据模式。
- 使用 SQLAlchemy 2 和 Alembic，不保留独立 SQLite 连接层及 SQL 脚本建表方式。
- 使用现有 FastAPI 应用，不启动第二个 8003 端口服务。
- 使用 V2 Glassmorphism 设计系统、应用壳和响应式规则，不直接复制原项目全局样式。
- 小说原文件和导出文件进入素材库，不保留独立 uploads 目录。
- 长耗时 LLM 操作进入后台作业，不在 API 请求线程内同步执行 30—60 秒。
- 所有新增数据必须按 `owner_id` 隔离；管理员可审计，但不能默认混用普通用户数据。
- 重要动作写入审计日志，作业进度通过轮询和 WebSocket 对外提供。

### 2.2 保留并迁移的 Novel2Script 能力

- TXT、DOCX、EPUB 小说解析与分章。
- 章节、段落稳定定位和原文溯源。
- 故事圣经：角色、地点、关系和关键事件。
- 场景切分、元素抽取、对白归属、改编决策、YAML 组装。
- V.O.、O.S.、动作、对白、转场等剧本元素语义。
- 五种改编手法：画外音、动作外化、潜台词、意象化、删除。
- Fidelity 评分、三幕结构、张力曲线和结构诊断。
- 单场精修、整本优化、版本分支与变更日志。
- Fountain、TXT、YAML 导出。
- JSON Schema 和引用完整性校验。
- 可脱离真实 LLM 运行的单元测试和降级策略。

### 2.3 不直接迁入的内容

- 独立 FastAPI `main.py`、CORS、健康检查和启动脚本。
- 原始 `sqlite3` connection/store 层和三份 SQL schema。
- 独立前端入口、Router、API client 和全局 CSS。
- 原项目无用户归属的 API 设计。
- 同步阻塞式完整编排接口。
- 独立 `.env` 和仅绑定 DeepSeek 的配置方式。
- 与当前实现不一致的历史说明，例如尚未实现的 PDF 导出。

## 3. V2.1 产品范围

### 3.1 本期必须交付

1. 剧本项目管理：新建、上传、列表、搜索、状态、删除和恢复入口。
2. 小说导入：支持 TXT、DOCX、EPUB，显示解析结果和异常章节。
3. 故事圣经：查看和编辑角色、地点、关系、事件，支持 AI 提取和 JSON 导入。
4. 剧本编排：后台执行，提供步骤、进度、日志、取消和失败重试。
5. 剧本工作台：原文与剧本对照、场景导航、元素展示和人工编辑。
6. 改编决策：展示五种方案，由用户确认选择，不允许 AI 静默替用户决定。
7. 质量报告：Fidelity、三幕结构、张力曲线、问题定位。
8. AI 优化：单场精修和整本优化，每次生成新版本。
9. 版本树：查看、切换、比较、命名和恢复为新版本。
10. 导出：Fountain、TXT、YAML，导出文件同步进入素材库。
11. 生成衔接：可将角色、地点或场景转换为现有图片/视频生成任务草稿。
12. 系统配置：OpenAI 兼容 LLM 服务、模型、超时和密钥配置。
13. 用户隔离、审计、响应式页面、功能开关和回滚方案。

### 3.2 V2.1 不包含

- 多人实时协同编辑、批注和审批流。
- Final Draft 原生 `.fdx` 导出。
- PDF 专业排版导出。
- 自动把整本小说一次性生成完整成片。
- 自建模型训练、向量数据库和角色声音克隆。
- 重写现有 ComfyUI 调度器为通用分布式队列。
- 移除 V1 或改变现有 V2 图片、视频、音频生成行为。

这些能力可进入 V2.2 以后规划。

## 5. 技术架构

### 5.1 目标形态

采用模块化单体，不采用 iframe 或第二套微服务：

```text
Vue V2 应用
  ├─ 剧本创作模块
  ├─ 现有生成模块
  ├─ 任务与作业中心
  └─ 素材中心
          │
          ▼
FastAPI /api/v2
  ├─ story API
  ├─ creative-job API
  ├─ resource API（复用）
  ├─ task API（复用）
  └─ generation API（复用）
          │
          ├─ Story pipeline worker（LLM/解析）
          └─ ComfyUI dispatcher（保持现状）
          │
          ▼
SQLAlchemy + Alembic + 统一素材存储
```

### 5.2 为什么不把 LLM 作业直接塞入现有 Task

现有 `Task` 强依赖 `Batch`、`GenerationType`、`WorkflowVersion` 和 ComfyUI 节点，`batch_id` 也是非空字段。强行复用会引入大量空值、虚拟工作流和调度分支，增加 V2 回归风险。

V2.1 推荐新建 `CreativeJob` 领域作业表，由独立 Story Worker 执行；任务中心在展示层聚合 ComfyUI Task 与 CreativeJob。这样用户看到统一任务体验，执行器仍保持清晰边界。

### 5.3 后台作业规则

- 作业类型：`parse_novel`、`extract_bible`、`compose_screenplay`、`optimize_scene`、`optimize_full`、`export_screenplay`。
- 状态：`PENDING`、`RUNNING`、`WAITING_USER`、`SUCCESS`、`FAILED`、`CANCELLED`。
- 每次作业记录当前步骤、总步骤、百分比、输入快照、模型配置快照、token 用量、错误和重试次数。
- 每个项目同一时间只允许一个写入型作业运行；只读导出可以并行。
- Worker 与 Web API 使用不同线程/事件循环，不能再次出现排队任务阻塞登录的问题。
- 应用重启后，超时的 `RUNNING` 作业转为可恢复或失败，不得永久占用。
- LLM 步骤按章节或场景设置检查点，失败重试不从头重复整个项目。

## 6. 数据模型规划

所有业务表使用整型主键、UTC 时间、SQLAlchemy 模型和 Alembic 迁移。

| 表 | 核心字段 | 用途 |
| --- | --- | --- |
| `story_projects` | owner_id、title、source_resource_id、status、current_version_id | 剧本项目根对象 |
| `story_chapters` | project_id、number、title、char_count | 章节 |
| `story_paragraphs` | chapter_id、position、text | 可溯源段落 |
| `story_bibles` | project_id、source、revision | 故事圣经主记录 |
| `story_characters` | bible_id、external_key、name、aliases、description | 角色 |
| `story_locations` | bible_id、external_key、name、int_ext、description | 地点 |
| `story_relationships` | bible_id、source_character_id、target_character_id、type | 人物关系 |
| `story_events` | bible_id、chapter_number、participants、description | 关键事件 |
| `screenplay_versions` | project_id、parent_id、origin、content、change_log、model_snapshot | 不可变剧本版本 |
| `adaptation_choices` | version_id、scene_key、element_key、choice、chosen_by | 用户改编选择 |
| `creative_jobs` | owner_id、project_id、type、status、progress、payload、error | 后台创作作业 |
| `creative_job_events` | job_id、type、progress、payload、created_at | 进度和运行日志 |
| `ai_providers` | name、base_url、model、secret_ciphertext、enabled | LLM 服务配置 |
| `story_generation_links` | project_id、version_id、scene_key、task_id、resource_id | 剧本与生成任务/产物关联 |

关键约束：

- 项目、版本、作业的所有读写都校验 `owner_id`。
- 剧本版本发布后不可原地覆盖；人工编辑也保存为新版本或受控草稿。
- `screenplay_versions.content` 初期使用 JSON 存储，YAML 仅作为导出格式，避免每次业务读写重复解析 YAML。
- 场景、角色等保留稳定 `external_key`，便于版本比较和原文溯源。
- 小说源文件、导出文件是 `Resource`；章节和剧本结构是数据库业务数据。
- 素材库扩展 `document` 类型，支持 TXT、DOCX、EPUB、YAML 和 Fountain 文件的图标、下载与筛选。
- 删除项目采用软删除；素材是否同步进入回收站必须由用户明确选择。

## 8. LLM 配置与安全

- 抽象为 OpenAI 兼容 Provider，默认可配置 DeepSeek，但代码不写死供应商。
- 管理员配置 `base_url`、模型、温度、超时、最大重试和并发数。
- API Key 后端加密存储，接口只返回掩码；日志和作业快照禁止保存明文 Key。
- 项目作业固定记录 provider/model 快照，后续能解释不同版本的生成差异。
- 设置系统级默认 Provider，后续可扩展用户自有 Provider。
- 增加成本保护：最大章节数、最大字符数、单项目并发和预估 token 提示。
- LLM 不可用时，文件解析、人工故事圣经、历史版本查看和导出仍可使用。

## 9. 前端工作台设计

### 9.1 项目列表

- 卡片/列表切换，显示封面占位、标题、章节数、场景数、当前版本和最后更新时间。
- 状态区分：待解析、待故事圣经、待编排、编排中、可编辑、失败。
- 支持关键字、状态、创建日期筛选，默认最近更新优先。

### 9.2 新建改编

- 上传区和“从素材库选择”并列。
- 选择文件后先显示格式、大小、文件名和解析预估，再创建项目。
- 支持 TXT、DOCX、EPUB；格式错误和空内容在提交前提示。

### 9.3 剧本工作台

- 左侧：章节、原文段落、当前场景来源高亮。
- 中间：场景列表和结构化剧本元素。
- 右侧：改编决策、质量问题、AI 优化入口和版本信息。
- 顶部：项目导航、保存状态、当前版本、版本切换、导出。
- 桌面端三栏可折叠；移动端使用页签和抽屉。
- AI 优化结果先显示变更摘要和差异，用户确认后切换到新版本。

### 9.4 与生成模块衔接

- 角色卡：创建角色设定图任务草稿。
- 地点卡：创建场景概念图任务草稿。
- 场景：创建分镜图或视频任务草稿。
- 自动带入结构化提示词，但必须允许用户检查和修改。
- 生成产物仍进入“任务结果 / 年月 / 日期”，并通过关联表回显到剧本项目。

## 11. 重新规划后的开发轮次

### 第 0 轮：基线、许可证与迁移清单

目标：冻结 V2.0，建立可回滚的 V2.1 开发起点。

开发内容：

- 建立 `codex/v2.1-story-integration` 开发分支。
- 记录 V2.0 后端 60 项测试和前端构建基线。
- 建立源文件迁移清单：复用、改写、淘汰三类。
- 核对 Novel2Script MIT License、提示词、Schema 和来源说明。
- 增加 `VITE_STORY_STUDIO_ENABLED` 与后端模块开关设计。
- 建立数据库备份和迁移回滚步骤。

验收：关闭开关时页面、API 和数据库行为与 V2.0 一致。

### 第 1 轮：领域模型与文档素材

目标：打通“上传小说—解析—查看章节”的非 LLM 链路。

开发内容：

- 新增 StoryProject、Chapter、Paragraph ORM 和 Alembic 迁移。
- 素材库支持 `document` 类型及 TXT/DOCX/EPUB 文件。
- 迁移三种解析器和格式校验。
- 新增项目列表、新建改编和项目概览页。
- 实现用户隔离、软删除和文件去重策略。

验收：三个格式均能从上传或素材库创建项目，章节段落顺序和原文字符数正确。

### 第 2 轮：创作作业与 AI 服务配置

目标：建立不会阻塞登录和普通 API 的 LLM 作业底座。

开发内容：

- 新增 CreativeJob、CreativeJobEvent、AIProvider 模型和迁移。
- 实现独立 Story Worker、心跳、取消、重试、恢复和并发控制。
- 迁移并抽象 OpenAI 兼容 LLM client。
- 新增 AI 服务配置、连通测试和密钥掩码。
- 新增创作作业列表、详情、步骤日志和 WebSocket 事件。

验收：模拟 60 秒 LLM 调用时登录、任务列表和素材库 API 仍可正常响应；服务重启后作业不会永久卡在 RUNNING。

### 第 3 轮：故事圣经

目标：提供可人工控制的角色、地点、关系、事件底稿。

开发内容：

- 新增故事圣经相关 ORM、Schema、Service 和 API。
- 迁移 AI 自动提取与 JSON 导入。
- 开发故事圣经 Web/移动端页面和表单校验。
- 增加重复角色合并、引用完整性和人工修订。

验收：用户可在 AI 不可用时手工维护；AI 提取结果必须先确认再进入正式数据。

### 第 4 轮：剧本编排流水线

目标：完成从章节和故事圣经到首版结构化剧本。

开发内容：

- 迁移场景切分、元素抽取、对白归属、改编建议、组装和评分模块。
- 迁移 Prompt、JSON Schema 和双层校验。
- 按章节/场景增加检查点、失败重试和降级结果。
- 新增 ScreenplayVersion、AdaptationChoice 模型。
- 作业详情显示各步骤调用次数、token、耗时和错误。

验收：可生成可校验的首版剧本；单章失败不会丢失其他已完成章节；所有版本归属当前用户。

### 第 5 轮：剧本工作台与改编决策

目标：完成 V2 风格的核心编辑体验。

开发内容：

- 开发桌面三栏、移动端三页签工作台。
- 实现章节/段落/场景联动和原文定位。
- 渲染动作、对白、V.O.、O.S.、转场等元素。
- 实现五种改编方案选择和人工编辑。
- 增加保存冲突检测和离开页面未保存提示。

验收：用户能够从原文定位到场景，选择改编方案并保存为新版本；移动端无横向溢出。

### 第 6 轮：质量报告、AI 优化与版本树

目标：形成可诊断、可优化、可回退的闭环。

开发内容：

- 迁移 Fidelity、结构分析和张力曲线。
- 开发单场精修、整本优化和变更预览。
- 实现不可变版本树、命名、比较和恢复为新版本。
- 展示 change log、模型快照和用户决策摘要。

验收：任何 AI 优化不覆盖原版本；用户可切换、比较和恢复历史版本；质量问题可定位到具体场景。

### 第 7 轮：导出、素材库与生成衔接

目标：把剧本模块接入 ComfyUI Console 现有生产链。

开发内容：

- 迁移 Fountain、TXT、YAML 导出。
- 导出文件创建 Resource 并提供下载。
- 增加角色、地点、场景到生成任务草稿的映射。
- 增加 StoryGenerationLink，项目内回显任务状态和产物。
- 任务中心聚合展示创作作业与 ComfyUI 任务，但保留各自详情结构。

验收：从一个场景可创建图片或视频草稿，用户确认后执行，结果可在项目和素材库双向访问。

### 第 8 轮：回归、性能、安全与灰度发布

目标：满足 V2.1 发布门禁。

开发内容：

- 迁移并适配 Novel2Script 可复用测试。
- 完整执行 V1、V2、V2.1 自动化与人工回归。
- 大文件、长章节、多版本和失败恢复性能测试。
- 权限越权、上传安全、路径穿越、密钥泄漏和 Prompt 日志审计。
- 完成功能开关、数据库备份、灰度发布和回滚演练。
- 更新 README、部署文档、API 文档和用户操作说明。

验收：所有门禁通过后才默认开放模块；关闭模块开关可立即隐藏入口且不影响原生成任务。

## 12. 测试门禁

### 12.1 后端

- 原 ComfyUI Console 60 项测试必须持续通过。
- 迁移 Novel2Script 的解析、Schema、编排、评分、版本和导出测试。
- 新增用户 A 无法读取/修改用户 B 项目的权限测试。
- 新增 Worker 心跳、重启恢复、取消、重试和并发限制测试。
- 新增 Resource 文档类型和项目/素材删除关系测试。
- 新增剧本到生成任务草稿的端到端服务测试。

### 12.2 前端

- `vue-tsc --noEmit` 零错误。
- Vite 生产构建通过。
- 项目创建、故事圣经、工作台、版本树和作业详情组件测试。
- 1440、1024、768、390 像素响应式验收。
- 长标题、长对白、100+ 场景和大量版本下无明显卡顿。

### 12.3 关键端到端场景

1. 上传三章 TXT，解析、提取故事圣经、生成首版、导出 Fountain。
2. 从素材库选择 DOCX，生成剧本后进行单场精修并切回原版。
3. LLM 中途失败，重试后从检查点继续。
4. 用户取消编排，已完成数据可查看，项目不处于假运行状态。
5. 从场景创建图片任务草稿，执行后产物回显到项目。
6. 两个用户同时操作，项目、作业、文件和版本完全隔离。

## 13. 发布与回滚

- 前端开关：`VITE_STORY_STUDIO_ENABLED=false` 时不注册菜单和页面入口。
- 后端开关：关闭时拒绝创建新 Story 作业，但允许管理员导出已有数据。
- Alembic 迁移只新增表和兼容字段，不修改现有 Task/Batch 核心约束。
- 先内部管理员开放，再按用户白名单开放，最后全量启用。
- 发布前备份数据库和 `backend/data/resources`。
- 回滚应用时保留 V2.1 表和素材文件，不执行破坏性降级；旧版本忽略这些新增表。

## 14. 主要风险与处理

| 风险 | 等级 | 处理方式 |
| --- | --- | --- |
| 同步 LLM 阻塞 API | 高 | 独立 Story Worker，API 只创建作业 |
| 原项目没有用户隔离 | 高 | 所有根对象强制 owner_id，服务层统一鉴权 |
| 两套 SQLite/ORM 冲突 | 高 | 全量迁移到 SQLAlchemy/Alembic，不保留 raw sqlite store |
| 长小说成本和失败率高 | 高 | 限额、预估、分段检查点、重试和部分成功 |
| 强复用现有 Task 导致回归 | 高 | CreativeJob 独立执行，展示层聚合 |
| API Key 泄漏 | 高 | 加密存储、掩码返回、日志脱敏 |
| 剧本版本被覆盖 | 中 | 不可变版本，编辑/优化均生成新版本 |
| 文档文件破坏素材库假设 | 中 | 显式扩展 document 类型和预览策略 |
| 原项目样式污染 V2 | 中 | 只迁移组件行为，使用 V2 tokens 重写样式 |
| 上游代码归属不清 | 中 | 保留 MIT License 和迁移来源清单 |

## 15. 交付完成定义

只有同时满足以下条件，V2.1 才视为完成：

- 用户在 ComfyUI Console 内完成小说上传到剧本导出的完整流程。
- 不需要启动 Novel2Script 独立后端或前端。
- 登录、素材库和现有 ComfyUI 排队任务不受 LLM 作业影响。
- 剧本项目、作业、版本和文件具有可靠用户隔离。
- AI 优化不覆盖历史版本，失败可诊断并可重试。
- 剧本角色、地点或场景可以创建现有生成任务草稿。
- V1/V2 原功能回归通过，功能开关和回滚演练通过。
- README、部署说明、迁移说明和第三方归属文档完整。

## 16. 推荐开工顺序

正式开发按“第 0 轮 → 第 8 轮”顺序推进，不建议先复制原前端编辑器。第一批代码应仅包含：

1. V2.1 功能开关和菜单占位。
2. StoryProject/Chapter/Paragraph ORM 与 Alembic。
3. 素材库 `document` 类型。
4. TXT/DOCX/EPUB 解析服务。
5. 项目创建、列表、详情 API。
6. 项目列表和新建改编页面。
7. 对应权限、解析和回归测试。

完成这一批后，再进入 LLM 作业底座。这样能先验证数据边界、用户隔离和素材复用，避免在架构未稳定时迁入整条 AI 流水线。
