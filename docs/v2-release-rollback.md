# V2 灰度发布与回退说明

## 发布前

1. 备份 `backend/data/app.db` 和 `backend/data/resources`。
2. 执行 `alembic upgrade head`，确认版本为 `0007`。
3. 运行后端测试、前端类型检查和生产构建。
4. 保持 `VITE_UI_V2_ENABLED=false` 完成首次部署，确认 V1 正常。

## 灰度启用

- `VITE_UI_V2_ENABLED=true`：打开 V2 总开关。
- `VITE_UI_V2_ROLLOUT_PERCENT=10`：先向稳定哈希命中的约 10% 浏览器开放。
- 逐步提升为 `25`、`50`、`100`，每阶段观察登录、错误率、提交成功率和队列等待时间。
- 用户可以返回 V1；选择记录保存在本机浏览器。

## 紧急回退

1. 设置 `VITE_UI_V2_ENABLED=false` 并重新构建前端。
2. V1 路由、接口和数据立即继续使用；无需降级数据库。
3. 保留 `0006/0007` 表和字段，以保证配置版本、任务快照和监控历史不丢失。
4. 只有确定不再需要 V2 数据时才执行数据库 downgrade，并且必须先备份。

## 运行检查

- 管理员访问 `/v2/settings/nodes` 查看调度心跳、节点探测和活动任务。
- 节点连续 3 次探测失败才标记离线，短暂网络抖动显示为 degraded。
- ComfyUI 丢失超过 5 分钟且不在远端队列中的 Prompt 会标记失败并释放执行槽。
- 管理员可手动释放异常任务，随后重新提交。
