# V2.1 第八轮验收：AI 小说分析与剧本改编

日期：2026-08-15

## 本轮目标

将小说转剧本从本地规则演示升级为可配置、可追踪、可恢复的真实 AI 创作链路，同时保留本地规则作为显式降级能力，不影响现有 ComfyUI 独立任务调度。

## 已完成功能

### 1. AI 模型配置

- 新增 V2“系统配置 → AI 模型配置”页面。
- 支持 OpenAI 兼容接口的名称、Base URL、模型、API Key、超时和最大输出 token 配置。
- 支持启用、默认模型、编辑、删除和连接测试。
- API Key 使用 Fernet 加密保存，查询接口只返回掩码提示。
- 普通用户只能读取已启用模型，新增、修改、删除和测试仅限管理员。

### 2. 小说结构化分析

- 小说按章节、段落及 12000 字符上限自动分块，避免长文本一次性提交。
- 分块提取剧情梗概、角色、地点、事件、时间线、钩子、事实及原文引用。
- 多分块结果由模型二次合并为版本化故事档案候选。
- 支持查看候选版本、结构校验问题以及人工确认；同一项目只保留一个已确认版本。
- 分析任务具备用户级幂等键，重复提交不会生成重复任务。

### 3. AI 改编方案

- 基于已确认或指定的故事档案生成剧集改编候选。
- 复用现有原文引用边界校验，避免改编结果引用不存在的章节或段落。
- AI 候选进入现有确认流程，确认后可继续世界设定、分镜和镜头生产。
- 页面仍保留“使用本地规则”，并与 AI 生成入口明确区分。

### 4. AI 创作任务与审计

- `CreativeJob` 新增模型配置、提示模板、父任务、模型、token 用量和预估成本字段。
- AI 分析与改编由独立 Story Worker 执行，不占用登录请求，也不阻塞 ComfyUI Dispatcher。
- 记录每次调用的模型、提示模板版本、请求快照、响应快照、耗时、token 和失败原因。
- 模型返回非法 JSON 时记录原始失败，并自动执行一次 JSON 修复任务。
- 应用启动时写入版本化系统提示模板，保证任务可追溯和测试可复现。

- AI 专项测试覆盖：密钥加密与脱敏、管理员权限、模拟 OpenAI 兼容接口、分析任务幂等、Worker 执行、token 统计、故事档案确认、AI 改编候选和跨用户隔离。

## 当前边界

- 当前 AI 能力覆盖“小说结构分析”和“剧集改编方案”，不是逐场、逐镜头正文生成器。
- 预估成本字段已预留，本轮未内置不同供应商的实时价格表，因此默认记录为 0。
- 系统提示模板已版本化保存，本轮暂不提供管理界面编辑。
- 实际模型调用需要管理员配置可访问的 OpenAI 兼容服务；自动化测试使用模拟服务，不会消耗真实模型额度。

## 下一轮建议

进入逐集剧本生产：在已确认改编方案上生成场次、对白和表演指令，增加逐集版本对比、局部重写、上下文预算、事实一致性校验和人工锁定机制。
