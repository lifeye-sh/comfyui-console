# ComfyUI Console V2 开发执行计划

> 计划版本：V2.0-P1
> 制定日期：2026-08-12
> 当前状态：待确认后开工
> 前置约束：V1 是稳定版；V2 独立开发、独立路由、可关闭、可回退。
## 1. 开发目标

V2 不是对 V1 的原地换肤，而是在复用稳定业务能力的基础上新增一套独立前端体验和配置能力。开发必须同时满足：

1. V1 功能和既有路由不变。
2. V2 使用 `/v2/*` 独立路由。
3. 未开启 V2 时，系统行为与当前版本完全一致。
4. V2 首期复用 `/api/v1` 的稳定任务、资源和工作流接口。
5. 新的数据模型和 `/api/v2` 仅用于 V1 不具备的生成类型版本化配置。
6. 每个迭代结束都必须可以部署、验证和回退。

## 3. 技术实施原则

### 3.1 前端目录

```text
frontend/src/v2/
├─ app/
│  ├─ V2AppShell.vue
│  ├─ V2Sidebar.vue
│  ├─ V2Topbar.vue
│  ├─ V2MobileNav.vue
│  ├─ navigation.ts
│  └─ featureFlags.ts
├─ design-system/
│  ├─ tokens.css
│  ├─ theme.ts
│  └─ components/
├─ components/
├─ features/
│  ├─ dashboard/
│  ├─ generation/
│  ├─ tasks/
│  ├─ batches/
│  ├─ resources/
│  ├─ workflows/
│  └─ generation-types/
├─ api/
├─ stores/
└─ routes.ts
```

V1 的 `frontend/src/views` 不移动、不重命名、不批量重构。

### 3.2 路由

```text
/                  V1 当前入口，保持不变
/gen/:code         V1 生成页
/tasks             V1 任务管理
/resources         V1 素材库

/v2                V2 系统概览
/v2/generate/:code V2 生成页
/v2/tasks          V2 任务管理
/v2/batches        V2 批次任务
/v2/resources      V2 素材库
/v2/prompts        V2 提示词库
/v2/videos         V2 参考视频
/v2/admin/*        V2 系统配置
```

### 3.3 状态和 API

- 认证 Token、当前用户和 WebSocket 客户端可共享。
- V2 页面不得直接依赖 V1 页面组件内部状态。
- 可复用 API 模块，但 V2 增加适配层，将接口响应转换为稳定 ViewModel。
- Blob URL、媒体播放器和轮询必须在页面卸载时释放。

### 3.4 CSS 隔离

- V2 样式以 `.v2-app` 为根作用域。
- 设计令牌使用 `--v2-*` 前缀。
- 不全局覆盖 Naive UI 或 V1 现有选择器。
- V2 深色主题只在 V2 根节点启用。

## 5. 首个开发批次

确认计划后，第一批只执行以下任务：

1. V2-001：建立 V1 回归清单。
2. V2-002：建立默认关闭的功能开关。
3. V2-003：创建 V2 独立目录。
4. V2-004：注册 `/v2` 独立路由和占位页。
5. V2-005：增加 V1/V2 切换和回退。
6. V2-006：运行并记录 V1 测试、类型检查和构建基线。

本批次明确不做：

- 不修改 V1 页面样式。
- 不迁移 Dashboard、生成、任务或素材页面。
- 不修改数据库结构。
- 不新增 `/api/v2`。
- 不改变默认入口。

## 6. 分支和提交策略

- 稳定分支：`main`。
- V2 集成分支建议：`develop/v2`。
- 功能分支：`feature/v2-<编号>-<简述>`。
- 每个任务至少一个可独立回退的提交。
- 合并前必须通过后端测试、前端类型检查和生产构建。
- 涉及数据迁移必须附带升级和回退说明。

建议提交格式：

```text
feat(v2-shell): add isolated v2 route and app shell
feat(v2-tasks): implement responsive task detail drawer
test(v1): add stable generation regression coverage
docs(v2): update iteration acceptance criteria
```

## 8. 风险优先级

| 优先级 | 风险 | 控制措施 |
| --- | --- | --- |
| P0 | V2 修改导致 V1 不可用 | 路由、目录、CSS 和开关隔离 |
| P0 | 动态配置影响历史任务 | 不可变版本和参数快照 |
| P1 | 毛玻璃影响性能和可读性 | 分层透明度、低性能降级 |
| P1 | 移动端复杂表单不可用 | 卡片化、逐步页、固定操作栏 |
| P1 | 素材预览占用大量内存 | 缩略图、并发限制、及时释放 Blob |
| P2 | V1/V2 重复逻辑难维护 | 共享 API/业务层，不共享页面状态 |

## 10. 开工判定

满足以下条件即可进入 Iteration 0：

- 确认 `/v2` 为首期独立入口。
- 确认 V2 默认关闭且不改变 V1 默认首页。
- 确认首批只建设隔离和骨架。
- 当前 `main` 分支保持可部署状态。
